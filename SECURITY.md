# Security policy

## Supported versions

TestWitness is pre-1.0. Security and privacy fixes are applied to the latest released `0.1.x`
version while MVP 1 is active.

## Reporting a vulnerability

Do not open a public issue for a suspected security or privacy vulnerability. Use GitHub's private
vulnerability-reporting option on the repository's **Security** tab when it is available. Otherwise,
contact a repository maintainer privately through their GitHub profile and request a secure reporting
channel before sending technical details.

Never send real evidence ZIPs, recordings, screenshots, credentials, cookies, tokens, customer data,
or private application URLs in an initial report. Use a minimal reproduction with synthetic data.

Include the affected version, browser and operating system, impact, sanitized reproduction steps,
and any suggested mitigation. Maintainers should acknowledge the report, investigate it privately,
coordinate a fix and disclosure timeline, and credit the reporter when requested and appropriate.
